### New Insights

**1. The `register_entry` → `OpenPosition` → `_calculate_partial_pnl` chain is fragile**

Adding a single field required changes in 3 places across 2 files. There's no validation that the caller passes the right value — if `pip_value_per_unit` defaults to 1.0 and nobody sets it, the currency conversion silently does nothing. The existing code for `oanda_trade_id` has the same pattern. V2's clean architecture (separate `models.py` with explicit constructors) handles this better.

**2. The OANDA 404 fallback is expensive**

The transactions API fallback I wrote fetches up to 6 hours of ORDER_FILL transactions and iterates through pages looking for the matching trade_id. For a bot running a 5-minute cycle, this could add 1-2 seconds per cycle when a trade closes between cycles. Not a problem with 1 concurrent position, but worth noting if max_concurrent_positions increases.

**3. The scoring system can now go negative**

With ranging (-20) + CT+POT (-15) + CT T1 (-10) stacking, a ranging counter-trend power_of_towers trade at Tier 1 could score as low as: base 30 (tier 1) + 5 (POT) + 20 (ATR) - 20 (ranging) - 15 (CT+POT) - 10 (CT T1) = **10 points**. The CAUTION regime penalty (-10) applied in main.py could push it to **0**, which would cause `_candidates = [c for c in ... if c['signal'].score > 0]` to filter it out entirely.

This is actually good — the worst combo in both audits (ranging + CT + POT + Tier 1) gets effectively blocked by low score, not by a hard gate. But I added a floor of 1 in main.py (`if signal.score < 1: signal.score = 1`) to prevent the regime penalty from causing score=0 (which means "validity-rejected" in the scoring system). A score of 1 will still lose every ranking competition to any reasonable trade.

**4. The overhead_cost_usd fix may cause slight discrepancies on existing open positions**

When V1 restarts, any position that was opened before the fix will have `overhead_cost` in quote currency (the old calculation) but `pip_value_per_unit = 1.0` (default). The P/L conversion check `pos.pip_value_per_unit != 1.0` will skip conversion for these legacy positions, which is the correct behavior — their overhead was calculated in the old way and the P/L should use the same basis. New positions opened after restart will use the correct USD-converted overhead.
